NAME

grepnet - Network-aware grep for CIDR blocks, IP ranges, and network addresses

SYNOPSIS

grepnet [OPTION…] PATTERN [FILE…]

grepnet [OPTION…] -f PATTERN_FILE [FILE…]

DESCRIPTION

grepnet searches for network addresses in text files using network algebra instead of substring matching. A pattern like 192.0.2.0/24 will match any IP address, CIDR block, subnet mask, or IP range that falls within that network—regardless of format.

This makes grepnet ideal for:

  • Network auditing: Find all references to a network across multiple files and formats
  • Configuration review: Locate which systems/applications reference specific networks
  • Security analysis: Identify networks referenced in logs, configs, and documentation
  • Network extraction: Extract and consolidate all networks mentioned in files

Core Concept: Network Matching

Unlike grep which does text matching, grepnet understands network topology. These all represent the same /24 network:

192.0.2.0/24             (CIDR)
192.0.2.0 255.255.255.0  (Subnet mask)
192.0.2.0 0.0.0.255      (Inverse mask)
192.0.2.0-192.0.2.255    (IP range)
192.0.2.0-255            (Short-range: octet-based notation)
192.0.2.1                (Single IP within the network)

A single grepnet '192.0.2.0/24' command finds all of these.

QUICK START

# Find any reference to a network (pattern can be any format)
grepnet '192.0.2.0/24' config.txt            # CIDR
grepnet '192.0.2.0 255.255.255.0' config.txt # Subnet mask
grepnet '192.0.2.0-192.0.2.255' config.txt   # IP range
grepnet '192.0.2.1' config.txt                # Single IP

# Search from stdin
echo "server 192.0.2.1" | grepnet '192.0.2.0/24'

# Search multiple files recursively
grepnet -r '10.0.0.0/8' /etc/

# Show line numbers and only matching networks
grepnet -n -o '192.0.2.0/24' data.txt

# Extract all networks from a file
grepnet --extract config.txt

# Consolidate overlapping networks
grepnet --consolidate networks.txt

PATTERN AND FILE INPUT

PATTERN
A single network address in any supported format. A pattern can be a CIDR block (e.g., 192.0.2.0/24), an IP range (e.g., 192.0.2.0-192.0.2.255), a subnet mask (e.g., 192.0.2.0 255.255.255.0), or a single bare IP address (e.g., 192.0.2.1). The tool automatically recognizes the format. You need only one pattern to search; use -P/--pattern for additional patterns if needed. See “Multiple Patterns” below for how to specify more than one.
FILE…
Files to search. If omitted, reads from stdin.
-P, --pattern PATTERN
Specify additional patterns beyond the first (repeatable for multiple patterns). Each pattern can be in any supported format independently.
-f, --patterns-file PATTERN_FILE
Read patterns from file, one per line. Each line is treated as a separate pattern in any supported format (repeatable to load multiple pattern files).
-F, --input-file FILE
Specify input file explicitly (alternative to positional FILE arguments)

Note on pattern flexibility: Each pattern is independent and can be any supported format. You don’t need to define every possible format or provide multiple patterns. A single pattern like 192.0.2.1 or 192.0.2.0/24 is sufficient for most searches. Patterns with -P or -f are purely optional and only needed when searching for multiple different networks.

MATCH TYPES

By default, grepnet returns networks that match the pattern (equals, subsets, supersets, overlaps) but NOT unmatched networks. Use these flags to filter by relationship type:

-e, --equal
Match only networks that are exactly equal
-s, --subset
Match only when file network is smaller than pattern (contained within)
-S, --superset
Match only when file network is larger than pattern (contains pattern)
-O, --overlap
Match only when networks partially overlap
-u, --unmatched
Include networks that don’t match any pattern (for use with other match type flags)

Clarification on -u (unmatched networks):

Default behavior (no flags): Returns networks that match the pattern in any relationship type (equals, subsets, supersets, or overlaps). Unmatched networks are NOT included by default.

With -u alone: Returns ONLY unmatched networks (those that don’t match any relationship type to the pattern). This is similar to -v but operates at the network level instead of the line level: while -v excludes entire lines without matches, -u excludes entire networks that matched any relationship type.

With -u and a match type filter: Returns both unmatched networks AND networks matching that specific filter type. For example, grepnet -u -s '192.0.0.0/16' data.txt returns networks that are either unmatched OR subsets of 192.0.0.0/16 (excludes supersets, equals, and overlaps). This is useful for finding networks to audit: “show me everything that either doesn’t match my pattern, or only matches as a subset.”

-v, --invert-match
Show lines that do NOT contain any matching networks (inverse logic; opposite of normal behavior)

Example with -v: grepnet -v '10.0.0.0/8' config.txt finds lines that do NOT contain any networks from 10.0.0.0/8 (useful for finding lines without internal networks)

EXTRACTION AND CONSOLIDATION

Network extraction and consolidation are two related operations for analyzing and simplifying network data:

Extraction (--extract): Scans input and finds all unique network objects (CIDR blocks, IP ranges, subnets, individual IPs). Deduplicates by network value (same network in different formats counts as one). Useful for discovering what networks are referenced in files, configurations, or logs.

Consolidation (--consolidate): Merges overlapping and adjacent networks into larger blocks, reducing complexity. For example, 192.0.2.0/25 and 192.0.2.128/25 merge into 192.0.2.0/24. This simplifies network inventories and highlights coverage gaps.

Output Formats: Extracted/consolidated networks can be output in multiple formats (CIDR, IP ranges, short-ranges, individual IPs, or original format).

Flags

--extract
Extract all unique networks found in input (deduplicated)
--consolidate
Consolidate overlapping and adjacent networks into larger blocks
--show-content
Include original line content in extract output (shows where each network was found)

Clarification on –show-content behavior: When used with --extract, this flag shows the original line from which each network was extracted. The format is:

<network>    <original line content>

This helps trace which configuration or context each network came from. This flag only works with --extract; it is not supported with --consolidate.

--format {cidr|range|short-range|ips|original}
Output format for networks (default: cidr)
  • cidr - CIDR notation: 192.0.2.0/24
  • range - Full ranges: 192.0.2.0-192.0.2.255
  • short-range - Abbreviated ranges: 192.0.2.0-255 (IPv4 only, last octet)
  • ips - Individual IP addresses, one per line (only with --consolidate)
  • original - Original format as found (not available with --consolidate)

Examples:

# Extract all unique networks
grepnet --extract network_logs.txt

# Consolidate overlapping networks into larger blocks
grepnet --consolidate all_networks.txt

# Extract networks matching a pattern, output as ranges
grepnet --extract -s '10.0.0.0/8' systems.txt --format range

# Consolidate and output individual IPs
grepnet --consolidate --format ips networks.txt

# Consolidate and show which lines contained each network
grepnet --consolidate --show-content config.txt

FILTERING

Filtering allows you to narrow or refine search results by excluding networks or matches that don’t meet your criteria. Two independent filtering approaches:

Text-based filtering (--exclude-string): Excludes individual network objects based on regex patterns matching the network as found in the source. Applied after network matching—a network object is excluded if its matched text (the exact string representation) matches the provided regex pattern. Useful for filtering by specific network representations or formats.

Network-based filtering (--exclude-cidr): Excludes network matches that have specific relationships to excluded CIDR blocks. The relationship is determined by --exclude-cidr-behavior. Useful for filtering by network hierarchy (e.g., exclude all internal networks, keep only external references).

Combining filters: Text and network filters are independent and stackable: - --exclude-string '192\.0\.2' --exclude-cidr '10.0.0.0/8' excludes network objects where the matched text matches “192.0.2” OR the network falls under 10.0.0.0/8 - Multiple --exclude-string or --exclude-cidr flags accumulate (any match causes exclusion)

Text Filtering

--exclude-string PATTERN
Exclude network matches whose matched text matches regex PATTERN (repeatable)
--exclude-strings-file FILE
Load text patterns to exclude from file

Behavior: For each network match found, test its matched text (the network as represented in the source) against each regex pattern. If any pattern matches, exclude that network object from results.

Network Filtering

--exclude-cidr NETWORK
Exclude specific networks (repeatable)
--exclude-cidrs-file FILE
Load networks to exclude from file
--exclude-cidr-behavior {subset|subset-strict|superset|superset-strict|equals|related|cut}
How to match excluded networks (default: subset)

Exclusion Behaviors

Control how excluded networks are matched:

  • subset (⊆): Exclude networks contained within excluded CIDR, including exact matches (default)
    • Use when: Filtering by network hierarchy (“exclude this network and anything inside it”)
  • subset-strict (⊂): Exclude networks strictly contained within excluded CIDR, excluding exact matches
    • Use when: Filtering all subnets of a network but keeping the parent network itself
  • superset (⊇): Exclude networks that contain excluded CIDR, including exact matches
    • Use when: Filtering broader networks (“exclude networks that encompass this range”)
  • superset-strict (⊃): Exclude networks strictly containing excluded CIDR, excluding exact matches
    • Use when: Filtering broader networks but keeping networks at the same level
  • equals: Exclude only exact matches
    • Use when: Blacklisting specific networks
  • related: Exclude any network that touches, contains, or is contained by excluded CIDR
    • Use when: Filtering all networks touching a specific range (strictest exclusion)
  • cut: Remove excluded network and return non-overlapping remainder blocks
    • Use when: Carving out excluded ranges and returning only the gaps (e.g., whitelist by exclusion)

Exclusion Examples

Scenario 1: Filter internal networks from results

# Exclude all private networks (default subset behavior)
grepnet --exclude-cidr '10.0.0.0/8' --exclude-cidr '172.16.0.0/12' \
  --exclude-cidr '192.168.0.0/16' '0.0.0.0/0' all_networks.txt

Scenario 2: Keep only subnets of a network, not parent networks

# Find subnets of 192.0.0.0/16, but exclude 192.0.0.0/16 itself
grepnet --extract --exclude-cidr-behavior subset-strict \
  --exclude-cidr '192.0.0.0/16' networks.txt

Scenario 3: Whitelist by exclusion (find only gaps)

# Find networks NOT in allowed ranges (carve out allowed space)
grepnet --extract --consolidate --exclude-cidr-behavior cut \
  --exclude-cidr '10.0.0.0/8' --exclude-cidr '192.168.0.0/16' all_networks.txt

Cut Behavior Details

The cut behavior is unique: instead of filtering out matched networks, it returns the complement—the “gaps” left after removing excluded networks. Useful for: - Finding unaccounted network space - Whitelist-based filtering (define what’s allowed, get everything else) - Network carving (subdivide networks by removing sections)

Example:

# Input networks: 10.0.0.0/8
# Exclude: 10.10.0.0/16
# Result: 10.0.0.0/22, 10.0.4.0/22, ..., 10.10.0.0/16 (gap), ..., 10.255.0.0/22
grepnet --extract --exclude-cidr-behavior cut --exclude-cidr '10.10.0.0/16' \
  --format cidr networks.txt

FILE DISCOVERY

File discovery controls which files are scanned when searching directories. This is critical for large directory trees where you need to focus on specific file types or exclude large backup/archive sections.

Default behavior: When no include/exclude filters specified, all files in the directory tree are scanned.

Include patterns (--include): Whitelist files matching glob patterns. Only files matching at least one include pattern are scanned. Can be specified multiple times (OR’d together).

Exclude patterns (--exclude): Blacklist files matching glob patterns. Files matching any exclude pattern are skipped. Can be specified multiple times. Applied after include filtering.

Directory-level exclusion (--exclude-dir): Faster alternative to --exclude. Skips entire directories without traversing them. More efficient than glob patterns on deep directory trees.

Symlink handling: - -r (default): Don’t follow symlinks (safer, faster) - -R: Follow symlinks (can cause infinite loops if circular links exist)

Glob pattern syntax: Uses standard glob wildcards: - * matches anything except / (doesn’t cross directory boundaries) - ? matches single character - [abc] matches character class - ** matches any path including / (if supported)

Example precedence:

Input: /var/log/2024/archived/app.log
--include '*.log' → Matches ✓
--exclude '*/archived/*' → Excluded ✗
Result: File NOT scanned

Flags

-r, --recursive
Search directories recursively (don’t follow symlinks; faster, safer)
-R, --dereference-recursive
Search directories recursively (follow symlinks; can cause infinite loops)
--include GLOB
Include only files matching glob pattern (repeatable; patterns OR’d together)
--exclude GLOB
Exclude files matching glob pattern (repeatable; patterns OR’d together)
--exclude-from FILE
Load exclude patterns from file, one per line
--exclude-dir PATTERN
Exclude directories matching glob pattern (repeatable; doesn’t traverse excluded dirs)

Common Patterns

Configuration auditing:

# Search only .conf and .yaml files
grepnet -r --include '*.conf' --include '*.yaml' '192.0.0.0/16' /etc/

Log analysis:

# Search logs excluding old archives and backups
grepnet -r --exclude-dir 'archive' --exclude-dir 'backup' \
  --exclude '*.gz' --exclude '*.zip' '192.0.2.0/24' /var/log/

Backup exclusion:

# Search everywhere except backups and cache
grepnet -r --exclude-dir '.git' --exclude-dir '__pycache__' \
  --exclude-dir 'node_modules' '10.0.0.0/8' /home/

Whitelist-based scanning:

# Only scan source code files
grepnet -r --include '*.py' --include '*.js' --include '*.go' \
  '192.0.0.0/16' src/

Performance tip: Use --exclude-dir instead of --exclude for large directories—it skips traversal entirely instead of checking each file.

PARSING CONTROL

Parsing control allows you to restrict which network formats grepnet accepts. This is useful for:

  • Enforcing consistency: Require all networks in a specific format (e.g., only CIDR)
  • Reducing false positives: Disable formats that might be ambiguous or commonly mistyped
  • Validation: Ensure input conforms to expected structure before processing
  • Format migration: Accept input in old format, require output in new format

Key concept: Each format type can be enabled/disabled independently for patterns (search terms) and input (data being searched). This allows asymmetric rules like “accept any format in input, but only CIDR in patterns.”

Default behavior: Most formats default to both (CIDR, netmask, hostmask, ranges, bare IP), except wildcard masks which default to none. This provides flexibility while preventing ambiguous wildcard matches by default.

Format Options

Each format flag accepts one of four modes:

  • pattern: Accept format only in search patterns (via -P, -f, or arguments)
  • input: Accept format only in data files being searched
  • both: Accept format in both patterns and input (default)
  • none: Disable format entirely

Flags

--parse-cidr {pattern|input|both|none}
Accept CIDR notation (e.g., 192.0.2.0/24; default: both)
--parse-netmask {pattern|input|both|none}
Accept subnet mask notation (e.g., 192.0.2.0 255.255.255.0; default: both)
--parse-hostmask {pattern|input|both|none}
Accept inverse/host mask notation (e.g., 192.0.2.0 0.0.0.255; default: both)
--parse-ranges {pattern|input|both|none}
Accept IP range notation (e.g., 192.0.2.0-192.0.2.255; default: both)
--parse-bare-ip {pattern|input|both|none}
Accept single IP addresses without CIDR notation (e.g., 192.0.2.1; default: both)
--range-format {long|short|both|none}
Accept long/short range formats (default: both) - long: 192.0.2.0-192.0.2.255 - short: 192.0.2.0-255
--parse-wildcard {pattern|input|both|none}
Accept Cisco wildcard mask notation (IPv4 only; default: none) - Wildcard masks use the format BASE_IP WILDCARD_MASK (e.g., 10.4.0.0 0.0.127.252) - Each bit in the mask: 0 = “must match”, 1 = “don’t care” (inverse of CIDR netmask semantics) - Represents a range: addresses where all 0-bits match the base address exactly, and 1-bits can be any value - Example: 192.0.2.0 0.0.0.192 matches addresses from 192.0.2.0 to 192.0.2.195 (192 = binary 11000000) - Commonly used in Cisco ACL rules: permit ip 10.4.0.0 0.0.127.252 any - Important: Wildcard mask parsing is disabled by default (none) to avoid false positives. Must explicitly enable with --parse-wildcard {pattern|input|both} AND provide --wildcard-search scope
--wildcard-search CIDR_SCOPE
Scope boundary for wildcard mask detection (default: not set; disables wildcard parsing) - Only wildcard masks whose mask value (second IP) falls within this CIDR block are recognized as valid - Format: Standard CIDR notation (e.g., 0.0.0.0/8, 0.0.0.0/16) - Prevents false positives by restricting which mask patterns are treated as wildcard masks - Must be narrower than /0 (rejects 0.0.0.0/0 as too broad to be useful) - Example: --wildcard-search 0.0.0.0/8 recognizes wildcard masks where the mask value falls in the 0.0.0.0/8 range - Combined with --parse-wildcard: Both flags are required to enable wildcard mask parsing - Typical usage: grepnet --parse-wildcard both --wildcard-search 0.0.0.0/8 pattern.txt
--scan-mask {pattern|input|both|none}
Detect netmask vs hostmask format hints from file content (default: both) - Analyzes the first 8 KB of files/patterns to determine whether netmask (255.255.255.0 style) or hostmask (0.0.0.255 style) format predominates - Provides hints to the parser for more intelligent extraction when formats are ambiguous - Scans only the enabled formats (respects --parse-netmask and --parse-hostmask settings) - Options: - pattern: Scan patterns only for format hints - input: Scan input files only for format hints
- both: Scan patterns and input files (default) - none: Disable hint detection; always use default MSB-based heuristics - Performance note: Reuses the 8 KB peek buffer from binary detection; zero additional file reads - Helpful when extracting from files with mixed or unknown format preferences

Common Use Cases

Enforce CIDR-only patterns:

# Only allow CIDR in search patterns; accept any format in data
grepnet --parse-cidr both --parse-netmask input \
  --parse-hostmask input --parse-ranges input \
  --parse-bare-ip input '192.0.2.0/24' data.txt

Strict format validation:

# Accept only CIDR everywhere; reject all other formats
grepnet --parse-cidr both --parse-netmask none \
  --parse-hostmask none --parse-ranges none \
  --parse-bare-ip none '192.0.2.0/24' data.txt

Accept flexible input, output CIDR only:

# Extract networks in any format from input, output as standardized CIDR
grepnet --extract --format cidr data.txt
# (No parsing flags needed; extraction normalizes everything to CIDR)

Bare IP only (no CIDR interpretation):

# Find exact IPs only; don't interpret as /32 networks
grepnet --parse-bare-ip both --parse-cidr none \
  --parse-netmask none --parse-hostmask none \
  --parse-ranges none 192.0.2.1 data.txt

Disable potentially ambiguous formats:

# Turn off bare IPs (often ambiguous in mixed data) and hostmask (rarely used)
grepnet --parse-bare-ip none --parse-hostmask none '192.0.2.0/24' data.txt

Match Cisco ACL wildcard masks:

# Search for networks using Cisco ACL wildcard notation
grepnet --parse-wildcard both --wildcard-search 0.0.0.0/0 \
  '10.4.0.0 0.0.127.252' acl-config.txt

# Result: Matches any line containing 10.4.0.0 0.0.127.252 or equivalent range
# Also matches CIDR 10.4.0.0/17 (same network) if --parse-cidr enabled

Extract networks from legacy Cisco configs (mixed formats):

# Accept netmask, hostmask, AND wildcard formats in input
# Patterns must use CIDR only (modern standard)
grepnet --parse-cidr both \
        --parse-netmask input \
        --parse-hostmask input \
        --parse-wildcard input \
        --wildcard-search 0.0.0.0/0 \
        --extract --format cidr legacy-config.txt

# Result: All networks normalized to CIDR, regardless of original format

Disable wildcard mask parsing:

# Reject wildcard mask formats (while still accepting others)
grepnet --parse-wildcard none '192.0.2.0/24' file.txt

Asymmetric Parsing Example

Scenario: Accept subnet masks in configuration files (old format), but patterns must use CIDR (modern standard).

grepnet --parse-cidr both \
        --parse-netmask input \
        --parse-ranges none \
        --parse-bare-ip none \
        '192.0.2.0/24' config.txt

Result: - Pattern 192.0.2.0/24 accepted ✓ (CIDR in pattern) - File line server 192.0.2.0 255.255.255.0 matches ✓ (netmask in input) - File line range 192.0.2.0-192.0.2.255 does NOT match ✗ (ranges disabled)

Automatic False-Positive Filtering

grepnet automatically detects and excludes common false-positive patterns that look like network addresses but are not. This prevents accidental matching of unrelated numeric patterns.

SNMP OID Exclusion

SNMP (Simple Network Management Protocol) uses OID (Object Identifier) notation that looks deceptively like IP addresses. OIDs are dot-separated numeric sequences like 1.3.6.1.2.1.1.1.0. Without filtering, bare IP parsing could mistakenly treat the OID components as individual IP addresses.

How it works: When a line contains an SNMP OID pattern (4+ dot-separated numeric parts with each part 0-4 digits), plain bare IP extraction is skipped for that line. However, CIDR notation, subnet masks, inverse masks, and IP ranges are still extracted normally, regardless of whether OIDs are present.

Why this distinction matters: - Bare IPs (e.g., 192.0.2.1) can be ambiguous in OID context—could look like OID components - CIDR notation (e.g., 10.0.0.0/8) is unambiguous—always a network object - Subnet masks, ranges, and inverse masks are also unambiguous—always network objects - Therefore, only bare IP extraction needs to be guarded against false positives

Example:

# File contains network configs and SNMP OID references
grepnet '0.0.0.0/0' config.txt

# File content:
# Line 1: "permit 192.168.1.0"
# Line 2: "snmp-trap-oid 0.3.6.1.2.1.1.0"
# Line 3: "network 10.0.0.0/8"

# Results:
# Line 1: permit 192.168.1.0                ✓ (bare IP extracted and matched as /32)
# Line 2: snmp-trap-oid 0.3.6.1.2.1.1.0     ✗ (OID line - 0.3.6.1 not extracted as bare IP)
# Line 3: network 10.0.0.0/8                ✓ (CIDR extracted and matched)

Why this matters: - SNMP monitoring and network configuration often appear in the same files - OID detection prevents false matches on numeric sequences that look like IPs but are actually OID components - This filter provides safe defaults without requiring manual --parse-bare-ip none flags for mixed config/monitoring files

Other False-Positive Filters

IPv6 embedding prevention: IPv6 addresses are not matched if they are embedded within larger identifiers or alphanumeric strings. For example, foo2001:db8::1bar will not match the IPv6 address inside, ensuring only standalone IPv6 addresses are recognized.

IPv6 zone ID rejection: IPv6 addresses with zone identifiers (e.g., fe80::1%eth0 or fe80::1%1) are not recognized. Only RFC 4291 standard compressed and uncompressed IPv6 formats are matched.

PREFIX LENGTH FILTERING

Prefix length (also called CIDR mask size or network mask bits) determines how many IP addresses a network block contains. Lower numbers = larger networks, higher numbers = smaller networks.

Prefix length basics: - IPv4: /0 to /32 (0 = entire internet, 32 = single IP) - IPv6: /0 to /128 (0 = entire IPv6 space, 128 = single IP) - Each increment halves the network size: /24 has 256 IPs, /25 has 128 IPs

Why filter by prefix length: - Audit subnetting: Find networks larger/smaller than policy allows - Simplify output: Extract only top-level aggregates or leaf subnets - Validate consistency: Ensure all networks are within expected size range - Find anomalies: Detect over-aggressive subnetting or under-utilized aggregates

Terminology clarification: - Shorter prefix = fewer bits = LARGER network (more IPs) - /8 is “shorter” than /24 (contains 65,536x more IPs) - Longer prefix = more bits = SMALLER network (fewer IPs) - /24 is “longer” than /8 (contains fewer IPs)

Flags

–ipv4-shorter-than N
Include only IPv4 networks with prefix length < N (larger networks)
–ipv4-longer-than N
Include only IPv4 networks with prefix length > N (smaller networks)
–ipv6-shorter-than N
Include only IPv6 networks with prefix length < N (larger networks)
–ipv6-longer-than N
Include only IPv6 networks with prefix length > N (smaller networks)

Common Use Cases

Find small subnets (more specific):

# Only /25 or smaller (more granular subdivisions)
grepnet --extract --ipv4-longer-than=24 networks.txt

# Result: /25, /26, /27, ... /32 only

Find large aggregates (less specific):

# Only /16 or larger (broad coverage)
grepnet --extract --ipv4-shorter-than=16 networks.txt

# Result: /0, /1, /2, ... /15 only

Find networks in a specific size range:

# Only class C or smaller (between /24 and /32)
grepnet --extract --ipv4-longer-than=24 --ipv4-shorter-than=32 networks.txt

# Result: /25, /26, /27, /28, /29, /30, /31 only

Audit IPv6 allocation (common /64 boundary):

# Find subnets smaller than standard /64 allocation
grepnet --extract --ipv6-longer-than=64 networks.txt

# Result: /65, /66, ... /128 (unusual, needs review)

Find policy violations:

# Policy: allocate in /25 blocks minimum
# Find anything smaller (over-subnetting)
grepnet --extract --ipv4-longer-than=25 violations.txt

Consolidation validation:

# Consolidate, then show only large aggregates (verify reduction)
grepnet --consolidate --ipv4-shorter-than=20 all_networks.txt

# Result: Only /0 to /19 (summary-level networks)

STRICT CIDR VALIDATION

CIDR validation ensures that network addresses don’t have “host bits” set. For example, 192.0.2.1/24 is technically invalid (host bits are set); the correct form is 192.0.2.0/24.

Why strict validation matters: - Consistency: Ensures all networks are represented canonically - Debugging: Catches typos (e.g., pattern meant to be 192.0.2.0/24 but written as 192.0.2.1/24) - Compliance: Some network configurations use CIDR notation to denote both the interface IP address and the network in one string (e.g., 192.0.2.1/24 means “configure IP 192.0.2.1 on the 192.0.2.0/24 network”). Strict CIDR validation distinguishes between these uses. - Safety: Avoid ambiguous network definitions

Default behavior: Non-strict (normalize silently). Malformed CIDRs like 192.0.2.1/24 are automatically corrected to 192.0.2.0/24 without warning. This provides flexibility but may hide mistakes.

Flags

--strict-cidr {pattern|input|both|none}
Where to apply strict CIDR validation (default: none)
  • pattern: Validate search patterns only (reject malformed patterns)
  • input: Validate data file content only (reject malformed networks found in files)
  • both: Validate both patterns and input
  • none: No strict validation (default; silently normalize)
--strict-cidr-action {fail|normalize|ignore|warn}
Action when invalid CIDR detected (default: normalize)
  • fail - Exit with error code 2 (stop processing)
  • normalize - Silently correct to network address (default)
  • ignore - Skip invalid CIDR (don’t include in results)
  • warn - Print warning to stderr, then skip

Use Cases

Audit configuration consistency:

# Reject any malformed CIDR in input; show warnings
grepnet --strict-cidr input --strict-cidr-action warn '192.0.2.0/24' config.txt

Enforce pattern validation:

# Reject if user types malformed pattern (e.g., typo in script)
grepnet --strict-cidr pattern --strict-cidr-action fail '192.0.2.0/24' data.txt

Strict everywhere with warnings:

# Both patterns and input must be valid; warn on violations
grepnet --strict-cidr both --strict-cidr-action warn '192.0.2.0/24' config.txt

Silent normalization (default):

# Accept `192.0.2.1/24`, automatically correct to `192.0.2.0/24`
grepnet '192.0.2.0/24' config.txt
# No warnings; output treats both as `192.0.2.0/24`

Visual Highlighting of Normalized CIDRs

When a CIDR has been normalized (host bits were corrected), grepnet can highlight it in output using the GREPNET_COLORS environment variable. The color key mn controls the appearance of normalized CIDRs.

Default: Normalized CIDRs are underlined (04)

Example: Highlight normalized CIDRs in red:

export GREPNET_COLORS="mn=01;31"
grepnet '192.0.2.0/24' config.txt
# Any network found as 192.0.2.1/24 (normalized to 192.0.2.0/24) will be displayed in red

This helps visually identify which networks required correction, making it easy to spot potential data quality issues without enabling strict mode errors.

Color code format: ANSI escape codes (e.g., 01;31 = bold red) - 01;31 - Bold red - 01;33 - Bold yellow - 01;36 - Bold cyan - 04 - Underline - 0 - Default color

Strict Validation with Extraction and Consolidation

Strict CIDR validation is especially useful with --extract and --consolidate modes, since these operations normalize all networks to canonical form and the distinction between correct and malformed input becomes significant.

Extraction behavior: - Non-strict (default): All networks extracted and normalized, no warning - Strict mode: Rejects/warns/skips networks with host bits set (depending on action) - Use case: Audit data quality before consolidation

Consolidation behavior: - Strict validation applies during extraction phase (before merging) - Consolidation result: Only valid networks are merged - Use case: Ensure consolidated output contains only canonical networks

Example: Audit and clean network data:

# Strict input validation with warnings, then consolidate
grepnet --extract --strict-cidr input --strict-cidr-action warn \
  --consolidate --format cidr config.txt

# Output: Only canonical networks, with warnings for any malformed input

Example: Identify data quality issues before consolidation:

# Show which networks needed normalization
export GREPNET_COLORS="mn=01;31"
grepnet --extract --format cidr config.txt

# Red-highlighted networks indicate data with host bits set
# Use --strict-cidr input --strict-cidr-action fail to reject these

BINARY FILE HANDLING

When searching directories, you may encounter binary files (executables, libraries, archives). By default, grepnet treats binary files specially to avoid corrupting output with unprintable characters.

Default behavior: Binary files are scanned, but if a match is found, the entire line is marked as “binary” and printed as Binary file <filename> matches instead of the actual match content. This prevents terminal corruption while still reporting which binary files contain matches.

When binary handling matters: Searching /usr/bin or other directories with mixed binary/text files, or scanning backups/archives alongside configs.

Flags

-a, --text
Treat all files as text (even binary files; raw output with potential corruption)
-U, --binary
Do not strip CR characters at EOL (MSDOS/Windows line endings; still respects binary file handling)
-I
Skip binary files entirely (do not scan; faster for mixed directories)
--binary-files {binary|text|without-match}
How to handle binary files (default: binary) - binary (default) - Report matches but show Binary file <name> matches instead of actual line - text - Treat as text (same as -a; raw output) - without-match - Exclude from results (same as -I)

Examples

Search directories with binary files (safe):

# Search /usr/bin with mixed binary/text files
grepnet '192.0.2.0/24' /usr/bin/
# Output: Shows "Binary file /usr/bin/curl matches" for binary matches
# No terminal corruption

Skip binary files (faster):

# Search config directories, ignore binaries
grepnet -I '10.0.0.0/8' /etc/ /opt/
# Only scans text files, skips binaries entirely

Force text mode (debug only):

# Treat binary as text (rarely needed; may corrupt output)
grepnet -a '192.0.2.0/24' /usr/bin/myapp
# Raw binary output

COMMENT FILTERING

Comment filtering controls whether networks inside comments are parsed and matched. By default, comments are stripped during network parsing to prevent false matches from commented-out configurations or documentation.

What gets filtered: - Pattern parsing: Comments in pattern arguments (e.g., grepnet '192.0.2.0/24 # my network' file.txt → comment stripped from pattern) - File content parsing: Comments in searched files (e.g., allow 192.0.2.0/24 # production → comment stripped before matching)

How it works: 1. Pattern parsing phase: Pattern arguments parsed; comments stripped; networks extracted from non-comment portion 2. File parsing phase: File lines parsed; comments stripped; networks extracted from non-comment portion
3. Matching phase: Extracted networks from patterns matched against extracted networks from files 4. Output phase: The original file line WITH comments is printed (comments appear uncolorized; see COLOR OUTPUT section)

Recognized comment markers: #, !, --, //, /* */, <!-- -->, ;

Recognized Cisco keywords (must be followed by whitespace or end of line): remark, rem, description, desc (case-insensitive). Can appear at start of line or after whitespace.

Critical distinction: The entire line is output when matched, but networks in the comment portion are NOT parsed, extracted, or counted in results.

Flags

--no-filter-comments
Disable comment filtering; parse and match networks even if they appear in comments (applies to both patterns and file content)

Realistic Examples

Configuration file with commented defaults:

Input file:
allow 192.0.2.0/24         # active rule
# allow 192.0.3.0/24       # commented rule

grepnet '192.0.0.0/16' config.txt

Default (comments filtered):
allow [highlighted]192.0.2.1[reset]          # active rule
(commented line skipped entirely)

With --no-filter-comments:
allow [highlighted]192.0.2.0/24[reset]       # active rule
# allow [highlighted]192.0.3.0/24[reset]     # commented rule

Why this matters for matching: - Default: Only active configurations are matched (commented rules are ignored) - --no-filter-comments: Both active and commented rules are matched (useful for auditing all references)

Impact on –extract and –consolidate

Comment filtering significantly affects data extraction and consolidation:

Default behavior (comments filtered):

grepnet --extract network.conf

Input file:
192.0.2.0/25
# 192.0.2.128/25
192.0.2.0/24

Output:
192.0.2.0/25
192.0.2.0/24
(commented 192.0.2.128/25 is excluded)

Then consolidate:
192.0.2.0/24 (result: 192.0.2.0/25 + 192.0.2.0/24 merge)

With –no-filter-comments:

grepnet --extract --no-filter-comments network.conf

Same input, but commented network IS extracted:
192.0.2.0/25
192.0.2.128/25
192.0.2.0/24

Then consolidate:
192.0.2.0/24 (result: all three merge into single /24)

Impact on network inventory: - Default: Your network inventory excludes commented configurations (cleaner, reflects “active” state) - --no-filter-comments: Your inventory includes all configurations (useful for compliance audits or finding forgotten commented entries)

Common Use Cases

Normal configuration auditing (comments filtered by default):

# Extract active networks from config files
grepnet --extract --consolidate firewall.conf

# Result: Only networks in active (non-commented) lines
# Commented networks like "# old: 192.0.2.0/25" are excluded

Full inventory audit (including commented configurations):

# Extract ALL networks including commented ones
grepnet --extract --no-filter-comments --consolidate firewall.conf

# Result: Comprehensive inventory including "dormant" commented networks
# Helps find forgotten commented-out entries

Verifying consolidation impact:

# Show difference between filtered and unfiltered
echo "=== Active only ==="
grepnet --extract --consolidate --format cidr config.txt

echo "=== All including commented ==="
grepnet --extract --no-filter-comments --consolidate --format cidr config.txt

# Difference highlights networks only in comments

Documentation extraction (with commented examples):

# Extract code examples from documentation that show network usage
grepnet --extract --no-filter-comments *.md *.rst

# Captures both networks in prose and in code/comments

COLOR OUTPUT

Colored output helps identify different parts of grepnet results at a glance. Each element (filename, line number, matched networks, match types, etc.) can have its own color.

Output structure with colors:

[filename]:[line_number]:[matched_line_content]

Different elements can be styled independently: - filename: File containing the match - line_number: Line number of the match - match_type colors: Different colors for equals/subset/superset/overlap/unmatched relationships - normalized_marker: Highlight CIDRs that required normalization (host bits stripped) - context_lines: Different style for context (non-matching) lines

Flags

--color {auto|always|never}
When to use colored output (default: auto)
  • auto: Colors on terminal output, plain text when output is piped or redirected
  • always: Force colored output even when piped (useful for terminal multiplexers, log files)
  • never: Disable colors (useful for scripts, CI/CD pipelines)

Example - Force colors even when piped:

grepnet --color always '192.0.2.0/24' *.txt | less -R
# -R tells less to interpret ANSI color codes

Customizing Colors with GREPNET_COLORS

Use the GREPNET_COLORS environment variable to customize any color element. Format: space-separated KEY=ANSI_CODE pairs.

Supported color keys:

Key Meaning Default
fn Filename 35 (magenta)
ln Line number 32 (green)
bn Byte offset 32 (green)
se Separator (: or )
sl Selected line background 0 (none)
cx Context line styling 0 (none)
mt Match text 0 (none)
ms Match separator within line 0 (none)
mc Match colon 0 (none)
me EQUALS match type 01;32 (bright green)
mb SUBSET match type 01;34 (bright blue)
mS SUPERSET match type 01;33 (bright yellow)
mo OVERLAP match type 01;31 (bright red)
mu UNMATCHED networks 0 (none)
wm Wildcard mask format (Cisco ACL) 4:3 (curly underline)
mn Normalized CIDR (host bits fixed) 04 (underline)

ANSI color codes (SGR - Select Graphic Rendition):

Basic codes: - 0 = Reset to default - 01 = Bold - 04 = Underline - 07 = Reverse video (inverse)

Foreground colors: - 31 = Red - 32 = Green - 33 = Yellow - 34 = Blue - 35 = Magenta - 36 = Cyan - 37 = White

Combining attributes (stackable ANSI codes): ANSI codes can be combined with semicolons to stack multiple attributes. Each key can have multiple codes separated by semicolons: - Combine 01 (bold) + color: 01;31 = bold red - Combine 04 (underline) + color: 04;32 = underlined green
- Combine 07 (reverse video) + color: 07;33 = reverse yellow - Combine multiple attributes: 01;04;35 = bold underlined magenta

Stackable attributes (can be combined with color codes): - 01 = Bold (makes colors brighter/more intense) - 04 = Underline (adds underline to text) - 07 = Reverse video (swaps foreground and background)

Stackable color keys (which keys can have attributes combined): Most color keys support combining bold/underline/reverse with a foreground color: - me, mb, mS, mo (match types): Can stack bold, underline, reverse with colors - mn (normalized CIDR): Can stack bold, underline, reverse with colors - fn, ln, bn, se, mt, ms, mc (structural elements): Can stack attributes with colors - mu (unmatched): Can stack attributes with colors - sl, cx (styling): Can use standalone attributes or with colors

Example stackable keys:

# mn (normalized CIDR) with bold red
export GREPNET_COLORS="mn=01;31"

# mn with underline and bold green
export GREPNET_COLORS="mn=01;04;32"

# Subset match type (mb) with reverse cyan
export GREPNET_COLORS="mb=07;36"

Not stackable (are mutually exclusive - use only one per key): - Foreground colors (31-37) - pick one color per key - Background colors (41-47) - if used, pick one background color

Common Customizations

Make all matches bright red:

export GREPNET_COLORS="me=01;31 mb=01;31 mS=01;31 mo=01;31"
grepnet '192.0.0.0/16' *.txt

grepnet --parse-wildcard both --wildcard-search 0.0.0.0/0 '10.0.0.0 0.255.255.255' acl.txt

Wildcard Mask Color Code (wm=): - Used only when --parse-wildcard is enabled - Highlights Cisco ACL wildcard mask format (e.g., 192.0.2.0 0.0.0.192) - Default: 4:3 (curly underline) - special SGR codes for underline style - Can be customized like other format codes (e.g., wm=01;35 for bold magenta) - Applies only to the matched wildcard mask text itself, not the entire line

High contrast for accessibility:

# Line numbers: bold green

Color Codes in Output

When colored output is enabled, ANSI escape sequences are embedded in the output. These look like [ESC[...m in raw form but render as colors in terminal emulators.

Example raw output (what’s in the terminal):

Renders as (what you see):

file.txt:42:[highlighted]192.0.2.0/24[reset] other text

Piping with colors: - Default (--color auto): Colors are removed when output is piped - With --color always: Colors are preserved (useful for less -R, more, etc.) - For scripts: Use --color never to avoid color codes in captured output

EXAMPLES

Basic Searching

Find all references to a network in a file:

grepnet '192.0.2.0/24' config.txt

Searches for all lines in config.txt containing any IP address within the 192.0.2.0/24 network.

Match a single IP against a CIDR pattern:

echo "192.0.2.50" | grepnet '192.0.2.0/24'

Accepts input from stdin; tests if 192.0.2.50 is within the pattern network.

Search multiple files:

grepnet '10.0.0.0/8' server1.txt server2.txt server3.txt

Searches all three files for any IP in the 10.0.0.0/8 range, with output grouped by file.

Search entire directory tree:

grepnet -r '192.0.0.0/16' /etc/

Recursively searches all files under /etc/ for networks in the 192.0.0.0/16 block.

Multiple Patterns

Using a single pattern is most common:

For most use cases, you only need one pattern. The pattern can be any format:

# CIDR notation
grepnet '192.0.2.0/24' data.txt

# IP range
grepnet '192.0.2.0-192.0.2.255' data.txt

# Subnet mask
grepnet '192.0.2.0 255.255.255.0' data.txt

# Single IP
grepnet '192.0.2.1' data.txt

When you need multiple patterns, use -P or -f:

Search for lines matching ANY of multiple patterns (logical OR):

grepnet -P '192.0.2.0/24' -P '10.0.0.0/8' data.txt

Each pattern can be in a different format:

grepnet -P '192.0.2.0/24' -P '10.0.0.0-10.255.255.255' data.txt

Read multiple patterns from file:

grepnet -f allowed_networks.txt config.txt

Reads patterns from allowed_networks.txt (one per line). Each line is a separate pattern in any supported format:

Example allowed_networks.txt:

192.0.2.0/24
203.0.113.0 255.255.255.0
198.51.100.0-198.51.100.255
10.0.0.0/8

All four patterns are valid; each can be a different format. The file has 4 patterns total, not 4 copies of the same pattern.

Match Type Filtering

Find only exact matches:

grepnet -e '192.0.2.0/24' networks.txt

Returns only lines containing exactly 192.0.2.0/24 or 192.0.2.0-192.0.2.255 (no 192.0.2.0/25, no 192.0.2.1, no 192.0.0.0/16).

Find networks contained within the pattern:

grepnet -s '192.0.0.0/16' all_networks.txt

Finds all subnets that fit inside 192.0.0.0/16: returns 192.0.2.0/24, 192.0.3.0/24, etc. Useful for policy audits: “which smaller networks have been allocated from this block?”

Find networks that contain the pattern:

grepnet -S '192.0.2.1' subnets.txt

Finds all networks where 192.0.2.1 is a member. If subnets.txt contains 192.0.0.0/16, 192.0.2.0/24, 192.0.2.128/25, all three match. Useful for traceability: “which networks claim this IP?”

Show all matches with their match types:

grepnet -P '192.0.0.0/16' -P '10.0.0.0/8' networks.txt

Uses grepnet’s default match-type coloring (if colors enabled) to show EQUALS (⊆⊇), SUBSET (⊆), SUPERSET (⊇), OVERLAP, or UNMATCHED.

Output Formatting

Show line numbers:

grepnet -n '192.0.2.0/24' config.txt

Prepends line numbers to output. Useful for referencing specific matches in large config files.

Show only the matched networks:

grepnet -o '192.0.2.0/24' data.txt

Extracts just the matching network/IP strings, one per line. Removes line numbers and context. Useful for creating lists of found networks for further processing.

Count matching lines:

grepnet -c '192.0.2.0/24' *.txt

Outputs count of matching lines per file. Use when you need statistics: “how many rules reference this subnet?”

Show only filenames with matches:

grepnet -l '192.0.0.0/16' *.conf

Lists only files containing matches (without the actual lines). Efficient for large file sets. Useful in scripts: grepnet -l pattern files | xargs process_files.

Count total matches across all files:

grepnet -c '192.0.2.0/24' *.txt | awk -F: '{sum+=$2} END {print sum}'

Combines -c with awk to get total matches across multiple files.

Context Display

Show 2 lines of context around matches:

grepnet -C 2 '192.0.2.0/24' config.txt

Displays the matched line plus 2 lines before and 2 lines after. Useful for understanding configuration context (e.g., seeing which rule/policy a network belongs to).

Show 1 line before, 3 lines after:

grepnet -B 1 -A 3 '192.0.2.0/24' audit.log

Asymmetric context: 1 line before (often the timestamp/event header) and 3 lines after (related details). Efficient for log analysis.

Context without group separator:

grepnet -C 1 --no-group-separator '192.0.2.0/24' file.txt

Displays context continuously without -- separators between groups. Cleaner output for piping or log analysis.

Display context with line numbers and colored matches:

grepnet -nC 2 --color always '192.0.2.0/24' audit.log | head -50

Combines line numbers, context, and colors for visual identification in large logs.

Network Extraction

Extract all unique networks from file:

grepnet --extract firewall_rules.txt

Scans the file, finds all network objects (CIDR blocks, ranges, bare IPs, etc.), and outputs each unique network as expressed in the input (deduplicates identical expressions only). For example, 192.0.2.0/24 and 192.0.2.0-192.0.2.255 are kept separate because they’re different representations. Use --format to normalize different representations to the same output format.

Extract and normalize to CIDR:

grepnet --extract --format cidr firewall_rules.txt

Converts all formats (netmask notation, ranges, bare IPs) to CIDR. Output is color-coded (if colors enabled): normalized CIDRs are underlined by default.

Extract networks matching a pattern:

grepnet --extract -P '192.0.0.0/16' all_networks.txt

Extracts only networks that are subsets of 192.0.0.0/16. Useful for extracting allocated subnets from a larger block.

Consolidate overlapping networks:

grepnet --consolidate all_subnets.txt

Merges overlapping/adjacent networks into minimal set. Input might have 192.0.2.0/24 and 192.0.3.0/24 as separate entries; output combines into 192.0.2.0/23 (if adjacent).

Output consolidated networks as ranges:

grepnet --consolidate --format range networks.txt

Shows consolidated result in IP range format (e.g., 192.0.2.0-192.0.3.255) instead of CIDR. Useful for some firewall/ACL formats.

Extract and show source lines:

grepnet --extract --show-content config.txt

Outputs both extracted networks AND the original config lines they came from. Useful for traceability: “this network is from this config line.”

Extract, consolidate, and save as new config:

grepnet --extract --consolidate --format cidr firewall_rules.txt > consolidated.txt
grepnet -f consolidated.txt application.conf  # now search using consolidated rules

Pipeline: extract all networks from rules, consolidate them, then use that consolidated set to search application configs.

Exclusion

Exclude networks matching a pattern:

grepnet --exclude-string '\.0$' '192.0.0.0/16' ips.txt

Finds all networks in 192.0.0.0/16, but excludes any whose matched text ends with “.0” (e.g., excludes bare IPs like 192.0.2.0 but keeps 192.0.2.1 and CIDR blocks like 192.0.2.0/24).

Exclude specific network from results:

grepnet --exclude-cidr '192.0.2.0/25' '192.0.2.0/24' data.txt

Finds all IPs in 192.0.2.0/24, but excludes the 192.0.2.0/25 subset (and anything smaller within it). Returns only 192.0.2.128/25 block results.

Exclude networks from file:

grepnet --exclude-cidrs-file banned.txt '0.0.0.0/0' networks.txt

Reads exclusion list from banned.txt (one network per line) and excludes all of them from search results. Useful for blocklist-style filtering: “show me everything except these networks.”

Exclude internal networks from search results:

grepnet --exclude-cidr '10.0.0.0/8' --exclude-cidr '172.16.0.0/12' \
  --exclude-cidr '192.168.0.0/16' '0.0.0.0/0' firewall.conf

Searches entire IP space but excludes RFC 1918 private ranges. Returns only public internet routes.

Exclusion with Strict Behavior

Default subset: include exact matches and containment:

grepnet --exclude-cidr '192.0.0.0/16' '0.0.0.0/0' networks.txt

Excludes 192.0.0.0/16 (exact match) AND 192.0.2.0/24 (subset). This is the default: if pattern is subset of exclusion, it’s removed.

Strict subset: exclude only exact matches:

grepnet --exclude-cidr-behavior subset-strict --exclude-cidr '192.0.0.0/16' '0.0.0.0/0' networks.txt

Excludes only 192.0.0.0/16 (exact match). Does NOT exclude 192.0.2.0/24 (subset of exclusion), returns 10.0.0.0/8 and 192.0.2.0/24. Useful: “I only want to exclude this specific network, not everything within it.”

Default superset: include exact matches and containment:

grepnet --exclude-cidr-behavior superset --exclude-cidr '192.0.2.0/24' '0.0.0.0/0' networks.txt

Excludes 192.0.2.0/24 (exact match) AND 192.0.0.0/16 (superset that contains it). Filters based on “anything that includes this network.”

Strict superset: exclude only exact matches:

grepnet --exclude-cidr-behavior superset-strict --exclude-cidr '192.0.2.0/24' '0.0.0.0/0' networks.txt

Excludes only 192.0.2.0/24 (exact match). Does NOT exclude 192.0.0.0/16 (superset). Useful: “I want to exclude this specific allocation, but keep the larger blocks.”

Recursive Searching

Find all references in configuration directory:

grepnet -r '192.0.0.0/16' /etc/

Searches all files under /etc/ recursively, printing matches with file:line format. Output is grouped by file.

Include only .conf and .yaml files:

grepnet -r --include '*.conf' --include '*.yaml' '10.0.0.0/8' /etc/

Filters to only .conf and .yaml files; binary and text-only files are skipped. Efficient when you know the file types.

Exclude backup directories:

grepnet -r --exclude-dir 'backup' --exclude-dir 'archive' '192.0.2.0/24' /var/

Skips entire backup and archive directory trees. More efficient than --exclude patterns because directory contents are not even traversed.

Search logs, exclude archived subdirectories:

grepnet -r --exclude '*/archive/*' '192.0.0.0/16' /var/log/

Pattern-based exclusion: any path matching */archive/* is skipped. Useful for excluding specific nested patterns.

Find files containing matches:

grepnet -rl '192.0.0.0/16' /etc/ | while read f; do echo "=== $f ==="; head -5 "$f"; done

Lists files, then displays first 5 lines of each. Quick overview of which configs reference a network.

Binary File Handling

Process binary files as text:

grepnet -a '192.0.2.0/24' data.bin

Forces binary files to be treated as text. Useful for config files that might have binary encoding or compiled configs (e.g., SQLite, protocol buffers).

Report binary matches without displaying content:

grepnet --binary-files without-match '192.0.0.0/16' *.bin

When binary file contains a match, report “match found” but don’t output the binary garbage. Useful for counting/logging without corrupting terminal.

Safely search mixed binary/text directory:

grepnet -r --binary-files skip '192.0.2.0/24' ./

Skips binary files entirely, searches only text files. Fastest approach when you know what you’re looking for.

Format Options

Search using netmask notation in patterns:

grepnet --parse-netmask pattern '192.0.2.0 255.255.255.0' data.txt

Allows patterns to use netmask format (base IP with subnet mask, space-separated). Matches against any format in input file.

Accept only CIDR format in input files:

grepnet --parse-cidr both --parse-netmask none --parse-ranges none --parse-bare-ip none '192.0.2.0/24' networks.txt

Enforces CIDR notation in input file; rejects netmask/range format. Useful for strict validation: “this file must use only CIDR.”

Extract and output as host/mask pairs:

grepnet --extract --format host-mask networks.txt

Output shows base IP and separate netmask (e.g., 192.0.2.0 255.255.255.0) instead of CIDR notation.

Prefix Length Filtering

Find subnets smaller than /24 (more specific):

grepnet --ipv4-longer-than=24 networks.txt

Returns all IPv4 networks with prefix longer than /24 (e.g., /25, /26, /27). Useful for finding over-allocation: “where are we subdividing too much?”

Find networks larger than /16 (less specific):

grepnet --ipv4-shorter-than=16 networks.txt

Returns all IPv4 networks with prefix shorter than /16 (e.g., /8, /12, /15). Useful for finding aggregates: “which large blocks do we own?”

Find exact prefix length:

grepnet --ipv4-prefix-length=24 networks.txt

Returns only /24 networks. Useful for compliance checking: “do we only allocate /24 to branch offices?” or “which networks don’t follow our standard?”

Find specific range of prefix lengths:

grepnet --ipv4-min-prefix-length=20 --ipv4-max-prefix-length=24 networks.txt

Returns networks between /20 and /24. Useful for policy validation: “all allocations must be between /20 and /24.”

Parsing and Comments

Search file with commented networks:

grepnet --no-filter-comments '192.0.0.0/16' config.txt

Enables parsing of networks in comments. By default, commented networks are ignored; this includes them in the search.

Show which networks are active vs commented:

# Count active networks only (default)
grepnet --extract config.txt | wc -l

# Count all networks including commented ones
grepnet --no-filter-comments --extract config.txt | wc -l

Useful for inventory: how many networks are actually active vs. how many are defined but commented out?

Extract only from non-commented lines:

grepnet --extract config.txt > active_networks.txt
# Then search using only active networks
grepnet -f active_networks.txt firewall.conf

Two-step pipeline: extract active networks, then use that whitelist.

Advanced Combinations

Whitelist-based filtering:

# Extract our authorized networks
grepnet --extract authorized.conf > our_networks.txt

# Find all mentions of our networks in logs
grepnet -f our_networks.txt /var/log/firewall.log

# Exclude any hits on internal networks
grepnet -f our_networks.txt --exclude-cidr '10.0.0.0/8' /var/log/firewall.log

Multi-step pipeline: define authorized networks, then search and filter strategically.

Blacklist-based filtering:

# Extract blocked networks
grepnet --extract banned_networks.txt > blocklist.txt

# Search logs, but exclude anything matching the blocklist
grepnet '0.0.0.0/0' /var/log/*.log --exclude-cidrs-file blocklist.txt

Inverted approach: search everything, then remove known/expected matches.

Audit network allocation:

grepnet --extract --consolidate corporate_allocation.txt > current_state.txt
diff <(sort previous_state.txt) <(sort current_state.txt)

Track changes in network allocation: “what new networks were added?”

Security audit:

grepnet -rn --exclude-cidr '10.0.0.0/8' --exclude-cidr '172.16.0.0/12' \
  --exclude-cidr '192.168.0.0/16' '0.0.0.0/0' /etc/ | grep -v 'approved\|expected'

Finds all external network references (excluding RFC1918), then filters to hide approved entries. Suspicious references stand out.

Recursive search with context, line numbers, and colors:

grepnet -rn -C 2 --color always '192.0.2.0/24' /etc/ | less -R

Combined flags for detailed investigation: -r (recursive), -n (line numbers), -C 2 (2-line context), –color always (force colors), piped to less -R for proper color rendering.

Find networks in logs, exclude internal, show counts per file:

grepnet -rc --exclude-cidr '10.0.0.0/8' '192.0.0.0/16' /var/log/*.txt

Lists count of matches per file. Useful for identifying which log files have the most activity for a given network.

Extract, normalize, and check for anomalies:

# Extract and normalize all formats to CIDR
grepnet --extract --format cidr all_networks.txt > normalized.txt

# Highlight non-standard allocations (e.g., odd prefix lengths)
grepnet --ipv4-longer-than=25 --ipv4-shorter-than=23 normalized.txt

Useful for finding “weird” networks that don’t match allocation policy.

Security Audits

Find all external networks referenced in system configuration:

grepnet -r --exclude-cidr '10.0.0.0/8' --exclude-cidr '172.16.0.0/12' \
  --exclude-cidr '192.168.0.0/16' '0.0.0.0/0' /etc/

Searches entire /etc tree for any external (non-RFC1918) network references. Useful for identifying unexpected internet connectivity rules or firewall policies.

Verify no deprecated/blocked networks are referenced:

BLOCKED="203.0.113.0/24 198.0.113.0/24"
for net in $BLOCKED; do
  if grepnet "$net" /etc/firewall.conf 2>/dev/null; then
    echo "SECURITY ALERT: $net found in firewall rules"
  fi
done

Checks specific blocked networks. Useful for ensuring deprecated ISPs or malicious networks aren’t accidentally whitelisted.

Find overly permissive rules:

grepnet --ipv4-shorter-than=16 firewall.conf

Identifies rules using large CIDR blocks (/0-/15), which may be unnecessarily broad. Useful for security hardening reviews.

Configuration Extraction and Management

Extract all networks from config files and consolidate:

find /etc -name '*.conf' | xargs grepnet --extract --consolidate --format cidr > all_networks.txt

Creates unified inventory of all networks across configs. Consolidated output merges overlaps, preventing policy contradictions.

Compare two configuration snapshots:

# First scan
grepnet --extract --consolidate config_old.txt > old_networks.txt

# After update
grepnet --extract --consolidate config_new.txt > new_networks.txt

# Compare
diff -u old_networks.txt new_networks.txt

Tracks network allocation changes: added routes, removed subnets, consolidation differences. Useful for change control logs.

Validate that two config files define the same networks (e.g., junos.conf vs cisco.conf):

# Extract and normalize networks from both files
grepnet --extract --format cidr junos.conf | sort > junos_networks.txt
grepnet --extract --format cidr cisco.conf | sort > cisco_networks.txt

# Compare - no output means they're identical
diff junos_networks.txt cisco_networks.txt

# Or check the result in a script
if diff -q junos_networks.txt cisco_networks.txt >/dev/null 2>&1; then
  echo "SUCCESS: Both configs define the same networks"
else
  echo "FAIL: Network definitions differ"
  echo "Networks in junos but not cisco:"
  comm -23 junos_networks.txt cisco_networks.txt
  echo "Networks in cisco but not junos:"
  comm -13 junos_networks.txt cisco_networks.txt
fi

Useful for multi-vendor configuration validation: verify that Juniper and Cisco configs have identical network definitions, or identify differences. The comm utility shows networks unique to each file (requires sorted input).

Build network documentation from active config:

grepnet --extract --format cidr --show-content firewall.conf | \
  awk '{print "- " $0}' > network_inventory.md

Generates markdown documentation with network and source line. Useful for policy documentation and change tracking.

Validate configuration format consistency:

# Extract all networks
FORMATS=$(grepnet --extract firewall.conf | grep -oE '(^[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+$|[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+/[0-9]+|[0-9]+-[0-9]+)')

# Check if all are CIDR
grepnet -f /dev/stdin <<< "$FORMATS" | grep -v '/' && echo "Non-CIDR formats found"

Identifies format inconsistencies, useful for standardization efforts (e.g., “migrate all to CIDR”).

ENVIRONMENT VARIABLES

GREPNET_COLORS
Customize output colors (space-separated KEY=ANSI_CODE pairs)

Supported color keys:

  • fn: Filename (default: 35 = magenta)
  • ln: Line number (default: 32 = green)
  • bn: Byte offset (default: 32 = green)
  • se: Separator (default: 36 = cyan)
  • sl: Selected line background (default: 0 = none)
  • cx: Context line (default: 0 = none)
  • mt: Match text color (default: 0 = none)
  • ms: Match separator (default: 0 = none)
  • mc: Match colon (default: 0 = none)
  • me: EQUALS match type (default: 01;32 = bright green)
  • mb: SUBSET match type (default: 01;34 = bright blue)
  • mS: SUPERSET match type (default: 01;33 = bright yellow)
  • mo: OVERLAP match type (default: 01;31 = bright red)
  • mu: UNMATCHED type (default: 0 = none)
  • mn: Normalized CIDR (default: 04 = underline)

ANSI codes are SGR (Select Graphic Rendition) values. Common values: - 0 = reset/no color - 01 = bold - 04 = underline - 31-37 = foreground colors (red, green, yellow, blue, magenta, cyan, white) - Combine with semicolons: 01;32 = bold green

Examples:

Customize all match types:

export GREPNET_COLORS="me=01;32 mb=01;34 mS=01;33 mo=01;31"
grepnet -e -s -S -O '192.0.2.0/24' *.txt
# Green for equals, blue for subset, yellow for superset, red for overlap

Highlight normalized CIDRs:

export GREPNET_COLORS="mn=01;31"
grepnet '192.0.2.0/24' config.txt
# Normalized CIDRs (those with host bits stripped) shown in bold red

High-contrast theme for presentations:

export GREPNET_COLORS="fn=01;37 ln=01;32 mb=01;36 me=01;32 mS=01;33 mo=01;31"
grepnet -e -s -S -O '192.0.0.0/16' configs/ | less -R
# Bold white filenames, green line numbers, bold match types, ANSI codes preserved with -R

Simplified output (no color):

export GREPNET_COLORS="fn=0 ln=0 me=0 mb=0 mS=0 mo=0"
grepnet '192.0.2.0/24' *.txt
# All colors disabled, plain output
